# Terminal on macOS

Enable **Terminal** in **Settings → Features**, then select its tab. It is off by default, including when upgrading an existing settings file. Enabling registers the tab; the first visit starts the account's login shell (`getpwuid`, with `/bin/zsh` as a fallback) in the home folder. It runs interactively with a real controlling pseudo-terminal and the normal shell startup files and environment, with `HOME`, `SHELL` and `TERM=vt100` set for that session. Shell commands have the same user permissions as QNotch.

The toggle hotkey (normally **Control-Option-N**) reopens the last tab with its input ready. Hover alone never takes the keyboard. Typing in Terminal stays in Terminal; **Command-F** or the Search hotkey opens Search. **Escape** is sent to the shell, so use the toggle hotkey, an outside click, or another normal panel-close action to collapse the panel. **Control-C** uses the PTY's line discipline to interrupt the foreground job. Return, Tab, Backspace, Delete, arrows, Home/End and Page Up/Down send terminal input. Option plus a character sends Escape followed by that character. AppKit text input supports composed input; the canvas shows marked text while composing. Drag to select output, **Command-C** to copy it, **Command-A** to select the retained output, and **Command-V** to paste plain text. Pasted newlines can submit commands. Embedded escape/control bytes are stripped from paste, apart from tabs and newlines; a paste larger than the 64 KiB input bound is refused in full.

Closing the panel, switching tabs, and sleeping preserve the session. Output continues to be consumed into a bounded in-memory screen while hidden, without redraws. The app writes no terminal transcript or terminal command history itself; your shell can write its own history and startup files normally. Disabling Terminal or quitting QNotch forcibly ends the owned PTY session's shell and jobs, closes the PTY master, and reaps its direct shell child. This includes normal foreground/background job-control groups, including jobs reparented when the shell exits. Jobs which deliberately create a new session (such as daemons launched with `setsid`) leave this ownership boundary and are not terminated. Other terminal/app sessions are never selected by name or killed. Descendants are reaped by their parent or the OS. A shell exit or startup failure shows a status message; toggle the feature off/on to create a fresh session. Unsaved work in the shell is lost when the feature or app stops.

## Renderer scope

This is a native bounded renderer for quick commands, not a full xterm emulator. It advertises `vt100`. It supports CR/LF, tabs, backspace, wrapping, cursor movement/save/restore, line/screen erase, character/line insert/delete, scrolling regions, ANSI bold/inverse and 16/256-color sequences, cursor visibility, application cursor keys, bracketed paste, cursor/status queries, and an alternate screen. Resize updates the PTY window size and the kernel sends SIGWINCH. Retained rows are clipped/padded rather than reflowed. The screen is clamped to 20–240 columns and 4–100 rows; scrollback retains at most 500 rows. Input queues and parser sequences are bounded, as are combining marks per cell. PTY reads are nonblocking batches, with kernel backpressure rather than an unbounded app output queue. After shell exit, up to 1 MiB of buffered final output is drained before closing; detached daemons retaining the slave cannot hold cleanup open indefinitely.

Unknown escape sequences are consumed. OSC/DCS strings are discarded without buffering their contents: no clipboard commands, hyperlinks, titles, images or file operations. There is no mouse reporting, DEC line-drawing character set, truecolor, complete function/modifier-key matrix, or full Unicode grapheme/bidirectional layout. Common CJK/emoji occupy two cells and basic combining marks are supported; complex emoji/ZWJ/variation-selector sequences can misalign. Advanced prompt themes, screen readers' terminal navigation, and sophisticated full-screen applications can exceed these limits. Use a dedicated terminal app for longer work or programs needing those features; this milestone has no “open in Terminal/iTerm” action.

## Verification and platform scope

Snapshots/smoke/measure use fixed sample output and a bounded fake input sink. They never launch the shell or execute terminal commands. The native smoke check `terminal-input-lifecycle` verifies hotkey focus, typing without Search interception, arrows, Ctrl-C, Escape, preserved output on close/reopen, focus when switching tabs, and disabling. XCTest separately exercises a real PTY with `/bin/sh` in a temporary home: tty stdio, controlling session, initial directory, dimensions/resize, interrupting a foreground job, shell reaping, owned background-job cleanup, and leaving another PTY session alive.

The product request also applies to Windows: its `src/QNotch/Modules/ModuleList.cs` has no Terminal module. This implementation is Mac-only; it adds no Windows behavior, release changes or external runtime dependency. Windows would need its own terminal backend (for example ConPTY) and renderer assessment.
